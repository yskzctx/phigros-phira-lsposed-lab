# Phira 原版 LSPosed 模块 0.1 开发候选

目标是官方 `org.flos.phira`，0.8.2（39），arm64。模块包名 `com.phira.lab.lsp`。APK 只包含约 41 KB 的适配代码，不替换原版引擎、不重新签名原版。尚未安装或真机验收，尚未公开发布。

## 当前候选的功能

- 音量上打开浅色面板，下关闭。采用宿主 Activity 对话框，不使用系统级最高层悬浮窗；关闭后音量下正常调节音量。
- 标准 AP 自动游玩由原版逻辑完成，冷启动默认关闭。模块只改普通配置选项，原版受保护成绩字段、检查及失败分支保留。
- 实验游玩启用原版离线结算；开启自动游玩后，本次会话使用原版不计成绩标记。原版网络权限保留，未统一断网。实际网络行为仍需真机验证。
- 通过原版已核对的导入接口导入 .pez/ZIP 谱面及完整皮肤资源包；原版资源包系统负责音符图片、特效、音效及判定线颜色，原版收藏夹和资源包页面负责管理。
- 独立实验存档内的历史全 AP，以及恢复修改前的历史记录，冷启动生效。
- 自动游玩会话恢复覆盖 `local_records` 和 `charts[].record`，保留新增谱面、皮肤和索引。

目标分数、目标准确率、逐音符判定规则和 RKS 编辑仍未接入，不能称为全功能移植。不能仅凭当前候选主机检查通过就说原版启动或所有资源包兼容。

## 数据与恢复

模块在 `<原版 getFilesDir()>/phira-lab-082/` 创建新的实验根目录。不会将原始账号或谱面索引复制到实验数据中；第一次读取原始 `data.json` 的私人备份保存在 `original-data-backup.json`，不要上传。

需要重新导入实验使用的谱面、皮肤。`history-before-edit.json` 保存首次历史编辑前的记录；`session-records.json` 用于下次冷启动恢复自动游玩会话。二者只保存记录，不用整个旧 data.json 覆盖当前内容索引。

退出 Phira，在 LSPosed 禁用模块，再冷启动，恢复原始数据路径。不要清除、覆盖或卸载原版。真实路径切换与禁用恢复仍需设备验收。

## 真机验收顺序

1. 安装模块，仅勾选原版 Phira，冷启动确认原版正常进入主页。
2. 手动导入一个合法自制谱和资源包，检查能播放音乐，图片/特效/音效/颜色正常。
3. 检查音量键面板；先关闭自动游玩手动测试，再开启标准 AP 测试并查看结算。
4. 检查实验记录的全 AP、恢复及会话重启；确认新导入内容保留。
5. 用设备日志及适当的网络检查验证模拟成绩没有上传。禁用模块并冷启动，检查原始记录和原版行为正常。

当前代码和主机测试已完成的范围见同目录 `host-verification.json`、`verification.json`，SHA-256 见 `SHA256SUMS.txt`。签名私钥、原版 APK/ELF、手机日志和私人备份均不在此目录内。
