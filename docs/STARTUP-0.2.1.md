# Phira 0.2.1 启动诊断修订

此修订补推荐作用域与启动诊断，尚未确认用户手机“原生接口未就绪”的底层原因，也没有宣称自动游玩已恢复。目标仍为官方 org.flos.phira 0.8.2（39）arm64；不放宽原生库 SHA 校验。

确定修正：清单增加 LSPosed 官方 legacy 推荐作用域 xposedscope；旧版仅有 assets/xposed_scope 不足以提供该清单声明。手动勾选正确游戏是有效设置，缺少推荐声明本身不能解释勾选后仍失败。

旧提示把“原生 Hook 安装完成、独立存档尚未激活”与其他未就绪状态混在一起。本修订分开显示，并增加阶段及 N/A/S/E/R/P/T 状态，不包含账号、令牌、存档内容或完整路径。连接报告可在模块入口复制。

操作：覆盖安装 Phira-Lab-LSPosed-0.8.2-arm64-v0.2.1-TEST.apk；在 LSPosed 启用并只勾选 org.flos.phira。到系统应用设置对 Phira 点“强行停止”，再从模块入口点“启动游戏并检查连接”。不要卸载游戏或清除数据，也不必重装 LSPosed。

如果仍不能开启，返回模块入口点“复制连接报告”，发出完整文字及 LSPosed 版本号即可，不需要连接电脑。若未收到报告，游戏面板运行状态也会显示同一阶段和诊断行。关闭最近任务卡片不保证原游戏进程已经退出。

状态：N 原生Hook就绪，A 独立存档激活，S 原生加载阶段（0未注册、1等宿主库、2找不到符号、3特征不符、4安装失败、5已安装），E 游戏提前运行，R 路径切换完成，P 收到路径调用次数，T 激活尝试次数。数字用于定位，不应手改为成功。

主机回归、APK签名/16KB对齐及公开源码与包内DEX/原生库/HTML一致性已核对；清单反编译确认 versionCode=3、推荐作用域为 org.flos.phira。真机启动和实际规则仍未验证。其他功能、数据隔离和原版上传流程不变，原始数据不覆盖。

官方参考：https://github.com/LSPosed/LSPosed/wiki/Module-Scope
