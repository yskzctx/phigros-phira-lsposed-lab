# Phira0.2.5：结算时间误差

仅更新Phira模块。宿主为官方org.flos.phira 0.8.2（39）arm64；模块versionCode8，可同签名覆盖0.2.4。安装后强行停止Phira再打开，不清游戏数据。Phigros模块继续使用[0.2.4](https://github.com/yskzctx/phigros-phira-lsposed-lab/releases/tag/v0.2.4-pre.1)。

## 怎么使用

在游戏内控制面板“游玩”页找到“结算时间误差”，填写目标毫秒值，例如20或20.5，点击“保存”，开启自动游玩后从下一张谱面使用。输入范围0～75ms，支持一位小数；0关闭此功能。重置游玩设置也会将它归零。设置保存在模块原有SharedPreferences内，冷启动后保留；自动游玩开关仍每次冷启动默认关闭。音量上键打开面板，下键收起。

结算显示的±ms与全连/AP是不同统计。当前已核对的0.8.2安卓版用原版commit累计偏差平方，原版result取sqrt(sum(diff²)/音符总数)，再由结算页面换算、四舍五入到毫秒。它不是音频校准，也不是把所有音符统一延后20ms。

本模块给计划为Perfect的音符分配随机偏早/偏晚的输入时机，单个计划偏差不超过75ms，在Perfect窗口内接近目标RMS。Good/Bad/Miss规则优先：先计入它们的平方贡献，再用剩余Perfect音符逼近目标；原版Miss按250ms计入，规则太多时最低误差可能已高于目标，面板会提示无法精确达到。误差启用后会按新时机重算连击/分数预估，目标分数仍是预估值。

**不改结算文字，不改原版受保护成绩字段，不把默认AP切换成官方自动游玩。** 面板显示目标、计划和本模块启用期间已判定事件的观测RMS；观测值不是直接读取原版结算。长条头尾处理、密集音符匹配、帧率与原版四舍五入会造成偏差，不保证设置20.5就恰好显示±21ms，最终以原版结算为准。
