# 0.2 诊断与界面修订 · 未发布

用户已报告游戏能出现模块菜单，因此 Java 部分确实进入了游戏。原先一句“版本、加载或路径不匹配”无法判断后续哪个环节失败。此次保留版本和函数特征保护，增加原生回调、游戏库符号、函数特征、Hook安装、提前运行、存档路径的分阶段诊断；没有把未经证实的初始化顺序猜测写成已修复的根因。

两个入口统一为浅色原生卡片、可读文字与明显主操作，提供“启动游戏并检查连接”。使用显式、一次性 PendingIntent 将非敏感状态返回模块自己的非导出 receiver，不开放跨应用可写的存档或配置；报告带时间，标明不是持续在线检测。没有报告不能断言作用域失效。

Phira 面板分为游玩、历史、连接。去掉模块里的重复导入入口，资源继续由原版管理。启动失败时仍能打开诊断面板，原生未加载不再被静默伪装成全零状态。

主要源码：两模块 InfoActivity.java、Dashboard.java、ConnectionReport.java、Entry.java；Phigros LabBootstrap.java；Phira Controls.java、DiagnosticState.java、LabNative.java、native/module.c；两个 AndroidManifest.xml 和构建版本号。

主机验证：Phira状态解码回归覆盖未注册、等待库、特征失败、提前运行、路径未切换、正常开关和异常格式；原有原始存档保持/实验存档恢复测试、配置字段与保护区不被改写测试、Phigros版本拒绝/隔离/回滚测试通过。两个APK签名与16KB对齐检查通过。真机界面、键盘、框架加载、真实游玩与网络行为均未验收。

未完成：Phira目标分数、目标准确率、逐音符规则与RKS；Phigros原生章节扩展特效、音效与判定线颜色。原版Phira成绩保护表示有完整性检查，直接补写路径已停止；未移除、伪造或绕过检查。现有诊断构建不能称为修改版全部功能的移植，也不对外发布为可用模块。

旧0.1公开下载保持撤回。无手机安装或操作。恢复方式仍为禁用模块、结束宿主进程后重启，不能覆盖或清除原始存档。
