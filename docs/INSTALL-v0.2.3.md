# 0.2.3 合并修复候选：两个模块

需要root与支持原生Hook的LSPosed。Phira-Lab-LSPosed-0.8.2-arm64-v0.2.3-TEST.apk只作用于org.flos.phira 0.8.2（39）arm64；Phigros-Lab-LSPosed-157-arm64-v0.2.3-TEST.apk只作用于com.PigeonGames.Phigros 4.0.1（157）arm64。两模块code6，可覆盖0.2.2；安装后在系统设置强行停止对应游戏再启动，不卸载或清除游戏数据。

这是修复候选，当前回归与打包检查通过，尚未验证这次修复在手机上的完整效果。仍使用模块自己的自动游玩，默认AP也没有切换到原版自带自动游玩。

## Phira：漏判与误触暂停

- 修正完整坐标链：事件像素先to_local，再由原版判定入口反转Y，最后做判定线逆变换；旧代码漏掉了中间Y反转。
- 模拟触点仅在Judge.update作用域内加入，返回时删除自己的事件；保留之前和之后的真实事件，暂停/菜单不会再读取本模块遗留触点。
- 自研触点采用原版已支持的谱面时刻哨兵，避免密集批次构造耗时形成输入时间偏差。
- 去掉1024个触点批次上限，输入容量与20000音符规划上限一致；组件测试覆盖2048个触点、旋转/位移、队列借用拒绝、真实事件保留与默认AP不启用原版AUTOPLAY位。

## Phira：直接使用原版现有存档

本次按用户要求取消数据/缓存路径重定向，继续使用宿主原来的files/data/data.json、谱面索引、皮肤、账号与设置；不再创建空白实验游戏目录。先前phira-lab-082内的数据保留，不删除，也不自动覆盖/合并进原档。

每次进入本模式时，先确保原版数据已在本机备份，备份失败不会启用修改。完整初始备份位置：

<Phira宿主getFilesDir()>/phira-module-backups/original-data-before-module.json

通常为 /data/user/0/org.flos.phira/files/phira-module-backups/original-data-before-module.json，实际以宿主路径为准。备份仅位于应用内部，不上传、不写日志，含私人账号数据，不要公开。

自动游玩开启前另存成绩快照session-records.json，下次启用模块冷启动时只恢复local_records与charts[].record，保留账号令牌更新、设置及新增谱面/皮肤。修改全AP前保留history-before-edit.json；面板“备份/恢复历史”用于恢复这份成绩备份，冷启动生效。直接在原档运行意味着本地历史操作确实会修改原档成绩，不能再把禁用模块当成成绩回滚。

需要完整回滚初始备份时：先强行停止游戏并禁用模块，另外保留当前data/data.json，再将完整初始备份内容恢复到原data/data.json，保留目标文件的原属主与权限。此操作会回退备份时的完整本地状态；日常仅回退成绩请优先用面板恢复历史。自动会话恢复需要下一次启用本模块冷启动，禁用状态下模块无法执行恢复。本地回滚不撤回已上传的数据。

## Phigros：共享判定实现修复

与修改版175共享同一原生修复：音符底层数组更换时使规则计划失效；用缓存索引代替每个音符反复扫描整张谱面，覆盖20000标识、重复/缺失键与数组替换。补默认AP四种按键、迟到帧、长条续判、时钟恢复和暂停/剧情阻塞回归。此实现没有使用Phira的共享触摸事件队列，不能把Phira的坐标/队列问题直接归给它。

Phigros模块本次保持已有独立实验存档方案；本次明确原档直连的改动针对正在反馈的Phira。Phigros修改版仍有自己的共存数据目录、无网络权限；它与正版的数据隔离要求不变。

## 测试与使用

无额外非完美规则时测试默认AP；明确配置的Miss/Good/Bad规则仍优先。优先用此前出现密集黄键误暂停和特殊谱面漏判的谱面核对，真实手指仍应能够正常暂停。若仍漏判，用游戏面板“复制诊断”提供本局统计和谱面信息，不能仅凭编译成功判断全部谱面已修复。

两个模块均保留原版登录与上传流程，原版和服务器决定接受与否；不取消账号、签名完整性或反作弊检查。Phigros原生章节扩展特效/音效/判定线颜色、Phira账号RKS等既有未完成项没有因此改变。

签名、16KB、主机C/JVM、原版输入/几何机器码和公开源码构建一致性已检查；没有手机全谱面、结算和真实上传验收。不要公开签名密钥、账号凭据、私人备份或设备日志。源码压缩包仅供构建者使用，安装无需下载。
